# 身份证识别

## 怎么调

用 shell 工具执行（`execute_shell_command`），一条命令一个文件：

```
ips idcard src/<文件名>
```

- 来源只能是本任务目录内的本地路径，**只支持图片（PNG/JPG/JPEG）**。指令里点名的文件已在 `src/` 下，把路径原样传进去即可。
- **PDF 不支持**：身份证检测接口只收图片。来源是 PDF 时不要调这条命令，改用 `extract_document_fields` 从 PDF 里取字段，并在结果里说明用的是通用抽取、不是证件专用通道。
- **禁止先下载**：不要 `curl`/`wget`（已被禁用），不要把指令里的 URL 当参数传。
- 多个文件逐条执行，命令一次只吃一个文件；同一文件不要调第二次（服务端有缓存，结论不会变）。
- 可选参数：`--init-confidence 0.6`（默认 0.5）、`--timeout 60`（秒）。默认值够用，别默认改阈值。

## 返回口径

标准输出是**恰好 1 个元素**的 JSON 数组（没检出不会返回空数组，而是走下面的 400）：

```
[{"confidence": 0.99, "idcard_type": 1, "ocr_text": "{...}", "corp_image_base64": null}]
```

**`ocr_text` 本身是一个 JSON 字符串，要再解析一层**才是字段。里面的接口口径字段名（不要改名）：
`姓名`、`性别`、`民族`、`出生`、`住址`、`公民身份号码`、`签发机关`、`有效期限`。

- 只有该面实际包含的字段有值，读不到的字段是**空字符串**——按缺失处理（写 null），不要从另一面、上下文或常识补出来。
- `idcard_type` 恒为 `1`，表示「身份证（按正面处理）」这一证件类别，**不是正反面编号**——检测模型不区分正反面，不要据此判正反。
- `corp_image_base64` 恒为 null，忽略，不要放进结果。
- 字段值一律取接口原文：姓名里的生僻字、住址里的门牌号、号码位数都不许「修正」或补全。`公民身份号码` 正常是 18 位（末位可能是大写 `X`），读成 17 位就写 17 位。
- 退出码 `0` 才是识别成功。

## 「不是身份证」也是结论

stdout 为空 + 退出码 `1` + stderr `错误: API 错误: HTTP 400 未检测到有效身份证.` 表示**这张图里没有可识别的居民身份证**——护照、驾照、银行卡、空白页、只拍到证件背面都会这样返回，这不是格式错误也不是失败。

- 这就是权威终局结论：不得改用 `extract_document_fields` 或 `understand_document` 去「补」身份证字段，也不要调阈值重试。
- 只有当任务要的是**其它单据/其它证件**的通用字段时，才改用 `extract_document_fields`，并在结果里说明它不是身份证专用通道给出的结论。

## 其它退出码

- `1` 且 stderr 是「文件不存在」等中文原因：原样转述，最多重试一次。
- `3`：`idcard` 子命令未开放（`IPS_ALLOWED_SUBCOMMANDS` 没放行）。直接说明无法识别，不要换别的命令绕过去。
- 不要用 `ips ocr` 读证件图片的原文——默认未开放，且会把无关全文灌进上下文。
