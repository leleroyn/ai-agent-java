# 发票识别

## 怎么调（照抄模板，只填文件路径）

用 shell 工具执行（`execute_shell_command`），一条命令一个文件。**整条命令照抄下面这一行，只把 `src/<文件名>` 换成实际路径，其它字符一个都不改**：

```
ips invoice src/<文件名> | python3 -c "print(*[o.get('ocr_text') or 'no_result' for o in __import__('json').loads(__import__('sys').stdin.read().strip() or '[]')] or ['not_detected'],sep=chr(10))"
```

这条模板做两件事：调增值税发票接口，再把返回里 `ocr_text` 那层 JSON 字符串解开，直接吐字段对象。

- **禁止自己写解析**：不要把上一条命令的 JSON 输出粘进新命令的源码里再解析一遍，也不要为了「整理/格式化 JSON」再起一条 python。粘过去要穿 4 层转义（bash 双引号 / 字符串字面量 / JSON / 接口原文），实测会炸，发票号码、金额数字、公司全称还会漏抄；那几百个字符还全算进生成量。路径之外，模板里没有任何需要改的东西。
- 模板输出是**一行（或多行，一份一页）合法 JSON 字段对象**，key 就是接口口径名（不要改名）：`发票号码`、`发票代码`、`发票类型`、`校验码`、`开票日期`、`购货方公司名称`、`销售方公司名称`、`发票金额`、`发票总金额`、`是否抵扣联`、`是否含有国税局印章`。**拿到这行就够作答了**，字段值原样抄进结果。
- 字段值一律取接口原文：**不要重新计算金额、不要合并或拆分数字、不要按位数「修正」号码**。空字符串字段按缺失处理（写 null）。
- 来源只能是本任务目录内的本地路径。**图片和 PDF 都可以直接传**，不用先转格式；指令里点名的文件已在 `src/` 下，把路径原样填进模板即可。
- **禁止先下载**：不要 `curl`/`wget`（已被禁用），不要把指令里的 URL 当参数传。
- 多个文件逐条执行，命令一次只吃一个文件；同一文件不要调第二次（服务端有缓存，结论不会变）。
- 可选参数加在 `ips invoice` 后面：`--init-confidence 0.8`、`--timeout 60`（秒）。默认值够用。
- `invoice_type` 是证照类别编号，`source_text` 与 `corp_image_base64` 常态为 null，忽略，不要放进结果。

常见说法到接口字段的对照：

| 任务里的说法 | 接口字段 |
| --- | --- |
| 购买方 / 买方 / 购货单位 | `购货方公司名称` |
| 销售方 / 卖方 / 开票方 | `销售方公司名称` |
| 价税合计 / 含税总额 / 发票总金额 | `发票总金额` |
| 金额合计 / 不含税金额 | `发票金额` |
| 开票日期 | `开票日期`（原文形如 `2023年02月24日`；要 ISO 格式就自己换算，数值不许改） |

## 输出 `not_detected` 也是结论

模板打印 `not_detected`（退出码 `0`，stderr 同时有 `错误: API 错误: HTTP 400 未检测到有效发票`）表示**这份文件不是中国增值税发票**——英文商业 invoice、形式发票、收据、合同都会这样返回。这不是格式错误也不是失败，是权威终局结论：

- 不得改用 `extract_document_fields` 或 `understand_document` 去「补」增值税发票字段，也不要重试。
- 只有当任务要的是**商业发票/其它单据**的字段（例如 ACME invoice 的 Invoice No、Total Amount）时，才改用 `extract_document_fields` 抽原文字段，并在结果里说明它不是增值税发票通道给的结论。

## 管道被白名单拒时（只允许 `ips` 的部署）

运维把 `AGENT_SHELL_ALLOWED` 设成只有 `ips` 时，第二段 `python3` 会被逐段白名单拒掉（模型收到 `SecurityError`，命令不执行）。**收到 `SecurityError` ＝ `python3` 整体不在白名单里：不要再换解析写法重试**，换 `python`/`jq`/`head`、换成 heredoc、换成短键名，只会拿到同一条拒绝。直接去掉管道，只跑：

```
ips invoice src/<文件名>
```

stdout 是**最多 1 个元素**的数组：`[{"confidence": 1.0, "invoice_type": 1, "ocr_text": "{...}", "source_text": null, "corp_image_base64": null}]`。**直接读**里面 `ocr_text` 那个 JSON 字符串取字段（key 同上）——不要为解析再起一条 shell。这种跑法下退出码 `0` 才是识别成功；stdout 为空 + 退出码 `1` + stderr「未检测到有效发票」＝上面那条「不是发票」。

## 其它退出码

- `1` 且 stderr 是「文件不存在」等中文原因：原样转述，最多重试一次。
- `3`：`invoice` 子命令未开放（`IPS_ALLOWED_SUBCOMMANDS` 没放行）。直接说明无法识别，不要换命令绕过。
- 不要用 `ips ocr` 读整张发票的原文——默认未开放，且会把无关全文灌进上下文。
