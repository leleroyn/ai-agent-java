# 发票识别

## 怎么调

用 shell 工具执行（`execute_shell_command`），一条命令一个文件：

```
ips invoice src/<文件名>
```

- 来源只能是本任务目录内的本地路径。**图片和 PDF 都可以直接传**，不用先转格式。
- 指令里点名的文件已在 `src/` 下，把指令里的路径原样传进去即可。
- **禁止先下载**：不要 `curl`/`wget`（已被禁用），不要把指令里的 URL 当参数传。
- 多个文件逐条执行，命令一次只吃一个文件；同一文件不要调第二次（服务端有缓存，结论不会变）。
- 可选参数：`--init-confidence 0.8`、`--timeout 60`（秒）。默认值够用。

## 返回口径

标准输出是**最多 1 个元素**的 JSON 数组：

```
[{"confidence": 1.0, "invoice_type": 1, "ocr_text": "{...}", "source_text": null, "corp_image_base64": null}]
```

**`ocr_text` 本身是一个 JSON 字符串，要再解析一层**才是字段。里面的接口口径字段名（不要改名）：
`发票号码`、`发票代码`、`发票类型`、`校验码`、`开票日期`、`购货方公司名称`、`销售方公司名称`、`发票金额`、`发票总金额`、`是否抵扣联`、`是否含有国税局印章`。

常见说法到接口字段的对照：

| 任务里的说法 | 接口字段 |
| --- | --- |
| 购买方 / 买方 / 购货单位 | `购货方公司名称` |
| 销售方 / 卖方 / 开票方 | `销售方公司名称` |
| 价税合计 / 含税总额 / 发票总金额 | `发票总金额` |
| 金额合计 / 不含税金额 | `发票金额` |
| 开票日期 | `开票日期`（原文形如 `2023年02月24日`；要 ISO 格式就自己换算，数值不许改） |

- 字段值一律取接口原文：**不要重新计算金额、不要合并或拆分数字、不要按位数"修正"号码**。空字符串字段按缺失处理（写 null）。
- 退出码 `0` 才是识别成功。

## 「不是发票」也是结论

stdout 为空 + 退出码 `1` + stderr `错误: API 错误: HTTP 400 未检测到有效发票` 表示**这份文件不是中国增值税发票**——英文商业 invoice、形式发票、收据、合同都会这样返回，这不是格式错误也不是失败。

- 这就是权威终局结论：不得改用 `extract_document_fields` 或 `understand_document` 去"补"增值税发票字段，也不要重试。
- 只有当任务要的是**商业发票/其它单据**的字段（例如 ACME invoice 的 Invoice No、Total Amount）时，才改用 `extract_document_fields` 抽原文字段，并在结果里说明它不是增值税发票。

## 其它退出码

- `1` 且 stderr 是「文件不存在」等中文原因：原样转述，最多重试一次。
- `3`：`invoice` 子命令未开放（`IPS_ALLOWED_SUBCOMMANDS` 没放行）。直接说明无法识别，不要换命令绕过。
- 不要用 `ips ocr` 读整张发票的原文——默认未开放，且会把无关全文灌进上下文。
